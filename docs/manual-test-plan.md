## 2. 执行方式

### 2.1 推荐：Obsidian 远程调试 + CDP 驱动

Obsidian 是 Electron 应用，用 `--remote-debugging-port` 启动后可由 Chrome DevTools Protocol 完整驱动（点击、输入、截图、读 DOM、抓控制台报错），这是覆盖率与可取证性最好的方式：

```bash
# 完全退出 Obsidian（Cmd+Q）后：
/Applications/Obsidian.app/Contents/MacOS/Obsidian --remote-debugging-port=9222 &
# 验证：
curl -s http://127.0.0.1:9222/json/version | head -5
```

连上后按用例操作，每条用例产出：**操作前截图 → 操作 → 操作后截图 → 控制台输出**。

### 2.2 必开：开发者控制台

`Cmd+Opt+I` 打开。**每条用例执行期间控制台出现任何 error 均记为缺陷**，即使界面表现正常。特别关注 `[ogenda]` 前缀日志。

### 2.3 取证要求

每条用例必须留存：用例 ID、操作步骤、实际结果、截图文件名、控制台片段。失败用例额外记录复现率（3 次中失败几次）。

## 5. 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| **P0** | 数据丢失/错乱、崩溃、核心流程不可用、同步写坏服务器数据 | 立即开 issue，标 `bug` + `P0`，阻塞发布 |
| **P1** | 主要功能结果错误但有绕行方案 | 开 issue，标 `bug` + `P1` |
| **P2** | 体验、文案、样式问题 | 开 issue，标 `enhancement` 或 `bug` + `P2` |

不合并、不打包。已有相同 issue 时补充复现信息而非新建。

```markdown
## 概述
```
