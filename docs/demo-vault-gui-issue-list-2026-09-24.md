# Ogenda `demo-vault` 测试 Issue 清单

> 来源：`docs/demo-vault-gui-test-report-2026-09-24.md`
> 基线：Ogenda 1.3.6、Obsidian 1.13.7、`demo-vault`
> 原则：只把可复现的产品/工程改进整理成 issue；外部凭据缺失、网络失败和 Computer Use 工具故障不冒充产品 bug。

## 建议创建

### ISSUE-01 — 为事件日期控件提供稳定的可访问输入语义

- **建议标题**：`[P2][enhancement] 为事件日期控件提供稳定的键盘与无障碍输入语义`
- **关联用例**：T3.1、T4.4–T4.11
- **现象**：Computer Use 可以看到 `mm/dd/yyyy` 日期控件，但无法通过可访问树稳定写入单一日期值；月份、日期、年份被拆成原生分段控件，自动化与辅助技术无法可靠完成新建/编辑往返。
- **期望**：日期控件至少提供稳定的 `aria-label`/可访问值；最好提供一个可键盘输入并能识别 `YYYY-MM-DD` 的单一入口，同时保留日历选择器。
- **验收**：新建定时事件、全天事件、结束日期校验、修改开始日期四条路径均可仅用键盘/无障碍接口完成并保存；保存后的 Markdown 日期准确。
- **证据**：本轮 CUA 表单截图与 AX 树；T3.1 被阻塞，测试数据未保存。

### ISSUE-02 — 建立可重复的 Obsidian Computer Use 手工验收入口

- **建议标题**：`[P2][test] 增加带远程调试和控制台采集的 demo-vault 手工验收入口`
- **关联用例**：T1.5、T2.1–T2.9、T6.1–T6.6、T8.1–T8.5、T12.8–T12.10
- **现象**：Obsidian 重启后截图仍可见，但无障碍树退化为空容器；坐标操作返回 `noWindowsAvailable`，导致视图点击、窄屏拖拽、触控和控制台零错误无法形成稳定证据。
- **期望**：提供一条文档化的测试启动命令，固定打开 `demo-vault`、远程调试端口、窗口尺寸和开发者控制台；测试完成后可安全退出并恢复备份。
- **验收**：同一环境连续执行 3 次，均可完成五视图切换、截图、控制台采集和窗口尺寸调整；失败时记录真实错误而不是静默跳过。
- **性质**：测试基础设施 issue，不是已确认的 Ogenda 业务缺陷。

### ISSUE-03 — 增加隔离的日历发现与同步 provider 测试夹具

- **建议标题**：`[P2][test] 为 iCloud/CalDAV/ICS 日历发现与同步矩阵增加隔离测试夹具`
- **关联用例**：T9.1–T9.13、T10.1–T10.16
- **现象**：本轮可确认同步空跑结果，但没有把真实 App 专用密码重新提交到外部服务，也没有对四种 provider 的 UI 切换和外部读写全部形成当前轮次证据。
- **期望**：使用专用测试日历或本地 CalDAV/ICS fixture，覆盖关闭、iCloud、通用 CalDAV、ICS 只读四种模式，避免使用生产日历和不可回滚的删除操作。
- **验收**：日历发现只返回 VEVENT 集合；VTODO 被过滤；新建/修改/删除/冲突/网络失败均有可重复断言；测试结束后 fixture 可重置。
- **性质**：测试环境与验收能力 issue；当前没有据此确认同步逻辑缺陷。

### ISSUE-04 — 补齐窄屏周视图的真实设备手工验收

- **建议标题**：`[P2][test] 补齐窄屏周视图 1/3/7 泳道与触控操作的手工验收`
- **关联用例**：T5.3、T6.1–T6.6、T12.8
- **现象**：源码和自动化已确认当前断点为 `<=360px` 单泳道、`361–720px` 三泳道、`>720px` 七泳道，并实现触控长按移动/拖动调整时长；本轮无法稳定改变 Obsidian 面板宽度或注入触控指针。
- **期望**：在 360、361、720、721px 边界，以及常见手机宽度下，确认周视图高度参考日视图、事件卡片能显示两行文字、三泳道为一般手机默认状态，移动/调整事件不误触发。
- **验收**：每个断点保留截图；至少完成一次触控新建、长按移动和底部调整时长；不出现横向溢出、事件遮挡或泳道跳变。
- **性质**：手工验收补充 issue；不能从本轮阻塞直接推断现有窄屏实现有 bug。

## 暂不建议创建

以下项目目前只有“未完成验证”或环境阻塞，不应直接创建产品缺陷：

| 项目 | 原因 | 后续动作 |
|---|---|---|
| T1.5 重启后 Agenda 是否自动激活 | 本轮只确认 vault 和插件恢复，未稳定复核激活页 | 在 ISSUE-02 环境中复测 3 次 |
| T8 密码显隐 | 没有重新进入设置页，不是失败证据 | 用隔离 UI 测试补齐掩码/明文/切换 provider |
| T9 日历发现 | 未提交真实外部凭据，避免向真实服务写入或泄露凭据 | 使用 ISSUE-03 fixture |
| T1.6 远端 tag 核验 | 当前 GitHub/Harness 网络或认证不可读 | 恢复网络/认证后单独核对，不改代码 |
| 同步网络异常 | 本轮未观察到新的业务错误，且已有重试机制 | 仅在可控 fixture 中复现后再决定是否开 bug |

## 当前处理建议

1. 先创建 ISSUE-01、ISSUE-02；它们分别解决表单可测性和手工验收可重复性。
2. 再准备 ISSUE-03 的隔离同步 fixture，完成外部 provider 矩阵。
3. 最后执行 ISSUE-04 的真实窄屏/触控验收；只有出现可重复的视觉或交互错误时，才拆出产品 bug。
