# ogenda D4-UI — Agenda 面板(清单/日/周/月只读展示) 设计文档

- 日期:2026-07-18
- 状态:已批准(brainstorming 会话确认,待写实现计划)
- 与 D4 原路线图的关系:D4 原定"多日历/多账户;`sync-collection` 增量;定时同步"是纯 CalDAV 后端扩展,和这次的 UI 面板**是两条独立的线**,互不阻塞、分开设计/实现。本文档只覆盖 UI 面板这一条线,暂称 **D4-UI**;原 D4 的后端项另开文档。

---

## 1. 背景与定位

现状:ogenda 目前没有任何自定义 UI——用户只能打开 `Agenda/*.md` 月度文件肉眼阅读原始 `## 标题` + `- key:: value` 文本,或者在命令面板里跑同步命令。

目标:参考 [Agenda Tasks 插件](https://github.com/elias-shalom/obsidian-agenda)(GitHub MIT,侧边栏多视图任务面板)的**交互细节**——不是照搬它整套 Overview/List/Table/Calendar 框架,而是"点事件能展开看/编辑、跟笔记实时联动"这种交互质感——给 ogenda 加一个专门浏览已同步事件的面板。

**核心心智模型(用户原话)**:"月度笔记文件是数据库,不是 UI"。月度文件继续是唯一的存储/同步真相来源(D1/D2/D3 的读写逻辑完全不变);这次新增的面板是**纯展示层**,只读 `MonthlyStore.readEvents()`,不引入任何新的持久化结构。

## 2. 目标 / 非目标

### 目标
- 一个新的 Obsidian `ItemView`,**主编辑区标签页**形式打开(不是侧边栏——面板信息量大,尤其日/周视图需要足够宽的空间)。
- 四个子视图:**清单 / 日 / 周 / 月**,顶部 tab 切换 + 翻页导航(‹ 今天 ›)。
- 循环事件(`rrule`)在面板里按实际出现日期展开显示(纯计算,不落盘)。
- 点事件跳转到其所在月度文件的原始章节(该处已经是可编辑的 markdown),面板侧留返回入口。

### 非目标(这轮明确不做,留到以后)
- **月度笔记文件本身的阅读视图卡片化渲染**(把 `## 标题` + 字段渲染成好看卡片)——这是另一个独立功能,下一轮单独头脑风暴。
- **面板内编辑**:改字段、建新事件、任何写操作。这轮点事件只做"跳转到原始笔记",不做单独的"事件详情"编辑弹窗/面板。
- D4 原路线图的**多日历/多账户/`sync-collection` 增量/定时同步**——完全独立的另一条线。
- 循环事件的**写回**(D2/D3 已经定过:循环事件写回是 D6 的事;这次只展开显示,不涉及写)。

## 3. 架构

```
AgendaPanelView (Obsidian ItemView, 主编辑区 tab)
  ├─ 状态:当前子视图(list/day/week/month)、当前锚定日期
  ├─ 数据:MonthlyStore.readEvents() → AgendaEvent[]（复用 D1/D2/D3 已有管线,只读）
  │         → 循环事件展开(ical.js RRULE 迭代,按当前视图可见日期范围现算)
  ├─ 渲染:四个子视图各自的渲染函数,原生 DOM API(createEl/createDiv),不引入 UI 框架
  └─ 交互:点事件 → app.workspace 打开对应月度文件 + 定位到该 heading;
           笔记侧留"返回面板"入口(具体机制——Obsidian 内置后退历史 vs 注入跳转
           链接——实现计划阶段再定,这里只定交互意图)
```

新增文件(实现计划阶段会精确到路径,这里先定模块划分):
- 一个新的 `ItemView` 子类 + 注册(`main.ts` 加 `registerView` + 打开面板的命令)。
- 一个"事件展开"模块:输入 `AgendaEvent[]` + 可见日期范围,输出展开后的出现实例列表(循环事件拆成多条,非循环事件原样透传)——纯函数,可单测。
- 四个子视图各自的渲染函数(每个职责单一,可独立理解/测试其"给定事件列表 → 生成什么 DOM 结构"这部分逻辑)。

## 4. 四个子视图详细设计

### 4.1 清单(List)
从"今天"起按时间顺序排列,按天分组(分组标题:今天/明天,或具体日期+星期)。每条事件是卡片式:左侧色条(区分全天/非全天)+ 时间 + 标题 + 地点,一行。

### 4.2 日(Day)
信息量最大的视图——完整展开日历字段:标题、时间、地点、说明、组织者、参与人、状态、RSVP、分类、标签、重复规则(有则显示,没有的字段整行不出现,不留空);下方原样展开散文笔记。**不显示**同步元数据(`uid`/`href`/`etag`/`base_hash`/`origin`/`source`/`protocol`/`server_deleted`)——这些是机器记账用的,对用户没有意义。

### 4.3 周(Week)
7 天一列的网格,每列内的事件是卡片式(时间+标题+地点),不做精确到小时刻度的时间网格(YAGNI,清单/日视图已经够精确)。

### 4.4 月(Month)
7 列星期网格。格子内每条事件用**缩略标题条**表示(不用圆点、不做"+N 更多"折叠)——一天事件再多,格子也要撑高到能显示全部标题条,不能因为空间问题让用户看不全当天有什么。

## 5. 交互:点事件之后去哪

点任意视图里的一条事件(清单/日/周/月都一样)→ 直接跳转到该事件所在月度文件的原始 markdown 章节。理由(用户原话):"月度笔记文件是数据库,不是 UI 界面"——原始笔记本身已经是可编辑的,不需要再造一个"事件详情"编辑面板。跳转位置留一个"返回日历面板"的入口,具体技术实现(复用 Obsidian 内置后退历史,还是在笔记里插入一个跳转链接)在实现计划阶段确定。

## 6. 技术选型

- **循环事件展开**:复用项目已有依赖 `ical.js` 的 RRULE 解析/迭代能力(`ICAL.Recur` 系列 API),不引入 `rrule.js` 等新依赖——避免功能重叠的包。
- **渲染**:延续项目现有的"零 UI 框架、原生 TypeScript"风格,用 Obsidian 的 `createEl`/`createDiv` 手写 DOM,不引入 Preact/Svelte——面板状态简单(当前 tab、当前日期范围、事件列表),不需要框架级响应式管理。

## 7. 与已有工作的关系

复用 D1-D3 已建的 `MonthlyStore`/`AgendaEvent`/`icalToEvents` 管线,面板是新增的纯读展示层,不改动任何同步/存储代码。参考的 [obsidian-agenda](https://github.com/elias-shalom/obsidian-agenda) 项目仅作交互细节参考,不复用其代码(MIT 协议,但架构/数据模型跟 ogenda 完全不同,没有直接复用的基础)。
