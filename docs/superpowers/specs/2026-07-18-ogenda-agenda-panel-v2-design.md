# ogenda Agenda 面板 v2 — CRUD + 分组 + 月度统计 + 时区设置 设计文档

- 日期:2026-07-18
- 状态:已批准(brainstorming 会话确认,待写实现计划)
- 前置工作:本设计建立在已完成并合并的 [D4-UI v1](2026-07-18-ogenda-d4-agenda-panel-design.md)(只读的清单/日/周/月四视图面板)之上,是同一个 Agenda 面板的下一轮迭代,不是新面板。

---

## 1. 背景与定位

D4-UI v1 上线并经过真机验证后,用户反馈两点:

1. **功能不够用**:面板完全只读,连新建日程都做不到——每次都要跳回月度笔记文件手改 markdown。
2. **界面设计不满意**:进一步核实后确认,这个反馈主要来自 v1 刚上线时"完全没有 CSS、纯文字堆叠"的那个版本(该问题已在 D4-UI 的 Task 8.5 里修过)。用真实的月视图/周视图色块 pill(参考 Agenda Tasks 插件)vs 现在的卡片风格做了并排对比后,用户两轮都选择保留现有卡片风格——**视觉框架本身是站得住的,不需要推翻重做**。

本轮设计聚焦第一点:把面板从"只读展示"升级为"可以直接创建/编辑/删除事件",同时补上清单分组、月度统计、时区设置三个配套需求。

**核心心智模型不变**(继承自 v1):月度笔记文件依然是唯一的存储/同步真相来源;这次新增的写操作,落地方式是"面板把改动正确写回本地月度文件",然后复用 D2/D3 已经建好的双向同步链路推到 iCloud——**不新增任何 CalDAV 交互代码**。

## 2. 目标 / 非目标

### 目标
- 面板内新建/编辑事件用完整表单(字段跟只读的"日"视图一样全),不用再跳笔记手改。
- 面板内删除事件(有二次确认)。
- 新建/编辑/删除后立刻自动触发一次双向同步(不用手动点同步命令)。
- 清单视图改为按 `status` 字段分组、组内按时间排序,支持组的折叠/展开。
- 面板新增"统计"tab,按自然月展示事件相关指标。
- 插件设置新增时区字段,覆盖面板所有"本地日期"判断,不受电脑系统时区影响。

### 非目标(这轮不做)
- 循环事件的编辑/写回(D2/D3 已经定过:循环事件写回是更后面的事;这轮创建的事件默认不带 `rrule`,已有的循环事件在面板里能看但暂不支持编辑其重复规则)。
- 清单视图除"按 status 分组"外的其他分组维度切换(比如按 category)——这轮只做单一的按 status 分组,不做分组维度切换器。
- 除"按 status 隐藏/显示 cancelled"外的筛选/搜索功能。
- D4 原路线图的多日历/多账户/`sync-collection` 增量/定时同步——继续是独立的另一条线,不受本轮影响。

## 3. A. 时区设置

- `OgendaSettings` 新增 `timezone?: string` 字段(IANA 时区名,如 `"America/Los_Angeles"`),设置页加一个对应输入框,留空 = 沿用电脑系统时区(现状行为不变)。
- 用 `Intl.DateTimeFormat` 的 `timeZone` 选项实现"给定一个 Date,取它在指定时区下的年/月/日分量",不引入新依赖(Electron/Node 自带,项目里的 `ical.js` 已经是唯一必需的第三方库)。
- 影响范围:面板里所有依赖"本地日期"的计算——`parseLocalDate`(D4-UI 修过的那个 all-day 解析函数)、"今天"锚点(`new Date()` 取当前日期部分的地方)、周/月视图的日期网格锚点。有配置时优先用配置的时区,没配置时保持原来"用运行环境系统时区"的行为不变(即 `Intl.DateTimeFormat` 不传 `timeZone` 选项)。
- 不影响:事件本身已有的 `tz` 字段(来自 iCloud VEVENT 的 TZID,是事件自己的时区,跟这个"面板显示用的本地时区设置"是两个概念,互不覆盖)。

## 4. B. CRUD

### 4.1 入口
- 面板顶部导航栏(跟"清单/日/周/月/统计" tab 同一行)常驻一个"+ 新建"按钮,任何 tab 下都能点,新建表单默认日期 = 当前面板的锚点日期。
- 周视图/月视图里,点击一个**空白**日期格子/列(没有已存在事件被点中)也触发新建,表单预填那一天的日期。
- 点击一个已存在的事件,弹出的是**编辑**表单(字段预填当前值),不再是"跳转到笔记"(v1 的"点事件跳笔记"行为被这轮的编辑表单取代;笔记跳转能力保留在代码里但不再是默认点击行为——具体入口位置留给实现计划阶段决定,比如表单里加一个"在笔记中查看"链接)。

### 4.2 表单
- 用 Obsidian 原生 `Modal` 类承载(弹窗覆盖在面板上方,关闭后面板恢复原状,不需要重新设计面板布局)。
- 字段跟只读"日"视图展示的字段对齐:标题(必填)、开始时间(必填)、结束时间、全天开关、地点、组织者、参与人、状态(status,下拉:confirmed/tentative/cancelled)、RSVP、分类(category,见 4.4)、标签(tags)。不包含同步元数据字段(uid/href/etag/base_hash/origin/source/protocol/server_deleted 这些依然完全不在任何用户可见的 UI 里,新建时由代码自动生成/留空)。
- 校验:至少要有标题和开始时间才能保存,否则内联报错、不关闭弹窗。
- 编辑时 `uid` 沿用原值;新建时生成一个新 uid(用现有项目里已经在用的 uid 生成方式,比如现有 `imapflow`/CalDAV 相关代码里事件 uid 的既有格式;具体生成函数在实现计划阶段确定)。

### 4.3 保存与同步
- 保存(新建或编辑)调用 `MonthlyStore.sync([event])`——这个方法内部的 `upsertEvents()` 本来就是"按 uid 存在则更新、不存在则新建",新建和编辑走同一条路径,不用分别写两套逻辑。
- **不阻塞 UI**:本地写入(`MonthlyStore.sync()`)成功后,弹窗立刻关闭、面板立刻重新渲染显示新/改后的事件——用户不用等网络请求。随后在后台(fire-and-forget,不 `await`)调用现有的 `syncBidirectional()`(跟"Sync iCloud (two-way)"命令背后是同一个函数,不新写同步逻辑)把改动推到 iCloud,这个后台调用同样是 D2/D3 已有的、`syncBidirectional()` 自带 `notify` 回调触发 `Notice` 汇报结果的模式(参照 `main.ts` 里 `caldavSyncTwoWay()` 命令回调的既有写法:`void syncBidirectional(...)`)。
- 若同步失败(网络问题等):事件已经稳稳地在本地文件里,不会丢;`syncBidirectional()` 的 `notify` 回调弹出 `Notice` 提示"已保存到本地,推送到 iCloud 失败(下次同步会重试)",不静默失败。
- 删除:点删除按钮先弹一个轻量确认对话框("确定删除《标题》吗?这会同步删除 iCloud 上的对应事件"),确认后调用 `MonthlyStore.removeByUid([uid])`,同样是本地删除立刻生效、`syncBidirectional()` 后台 fire-and-forget 触发(复用 D3 已经建好的"本地消失的已同步事件 → 下一轮识别为 deleteRemote → 推 DELETE"链路)。

### 4.4 分类(category)输入
- 编辑表单里的分类字段是一个下拉框:选项来自 vault 里所有月度文件中已经出现过的 `category` 取值(去重),外加一个"输入新分类..."选项(选中后变成文本输入框)。避免同一个分类打出"工作"/"Work"两种没法归到一起的情况。

### 4.5 迷你日历
- 日视图旁边(参考 Agenda Tasks 的日视图布局)加一个迷你月历组件:显示当前锚点日期所在月份的完整月历网格,点某一天 = 把面板锚点跳到那天(日/周/月视图共用同一个锚点日期状态,所以这个跳转对三个视图都生效,不只是日视图)。

## 5. C. 清单视图分组

- 清单不再是"从今天起按天摊平分组",改成**按 `status` 字段分组**(confirmed / tentative / cancelled 三组,没有 status 值的事件归入一个"未设置"分组),组内事件按开始时间正序排列(组内不再按天二次分组)。
- 每个分组标题可以点击折叠/展开,默认全部展开;折叠状态不跨会话记忆(每次重新打开面板,面板重置为全展开)。
- cancelled 状态的事件默认照常显示,不隐藏——这轮不做筛选/隐藏功能。

## 6. D. 月度统计

- 面板顶部 tab 从"清单/日/周/月"四个扩展到**五个:清单/日/周/月/统计**。
- 统计 tab 有自己的锚点日期(复用面板已有的锚点状态)+ `‹ 今天 ›` 翻页,按**自然月**(不是滚动窗口)计算指标,翻页 = 换到上/下一个自然月。
- 展示指标:
  1. 本月事件总数
  2. 按 status 分布(各状态各多少条)
  3. 全天事件数 vs 定时事件数
  4. 循环事件数(带 `rrule` 的事件主体数,不是展开后的出现次数) vs 单次事件数
  5. 按 category 分布(每个分类多少条,没有分类的归入"未分类")
  6. 最忙的 3 天(当月事件数最多的 3 天,按数量降序)
  7. 未同步到 iCloud 的本地改动数(即 `local.hasHref === false` 或字段哈希跟 `base_hash` 不一致的事件数——复用 D2 已有的"本地是否有未同步改动"判断逻辑,不新造一套)

## 7. 技术选型

- **表单承载**:Obsidian 原生 `Modal`(`obsidian` 包自带,无需新依赖)。
- **时区计算**:`Intl.DateTimeFormat`(浏览器/Node 内置 API),不引入 `date-fns-tz`/`luxon`/`moment-timezone` 等新依赖。
- **CRUD 存储层**:全部复用 D1-D3 已有的 `MonthlyStore.sync()`/`MonthlyStore.removeByUid()`/`syncBidirectional()`,不新增任何 CalDAV 读写代码。
- **UI 渲染**:延续 D4-UI v1"零框架、原生 DOM API"的风格,表单和迷你日历也用原生 DOM 手写,不引入 Preact/Svelte。

## 8. 与已有工作的关系

这轮是 D4-UI v1(清单/日/周/月只读面板)的直接延伸,复用其全部现有代码(`occurrences.ts`/`date-grid.ts`/`navigate.ts`/四个视图渲染器/`AgendaPanelView`),只做增量修改(清单视图的分组逻辑替换、新增统计 tab、新增 CRUD 表单和迷你日历、`AgendaPanelView` 接入新建/编辑入口)。时区设置是插件设置层面的独立小改动,不依赖本文档其他部分,可以在实现计划里作为独立的一个/几个任务先行完成。
